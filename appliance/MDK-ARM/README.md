# Keil MDK-ARM project (appliance)

`Quilla.FR.uvprojx` builds the same FreeRTOS APP as `../gcc/Makefile`, with
**ARM Compiler 5** (armcc v5, `uAC6 = 0`) and the Puya PY32F0xx DFP. Device:
`PY32F040CxB`, 128 KiB Flash / 16 KiB RAM.

## Key settings

| Item | Value |
| --- | --- |
| IROM1 | `0x08007000`, size `0x19000` (behind QBOOT + META) |
| IRAM1 | `0x20000000`, size `0x4000` |
| Defines | `USE_HAL_DRIVER,PY32F040xB,QAPP_BUILD` |
| Scatter | `.\Objects\Quilla.FR.sct` (auto-generated by Keil) |
| FreeRTOS port | `portable/RVDS/ARM_CM0` (not the GCC port) |
| Post-build | `fromelf --bin -o "$L\Quilla.FR.bin" "#L"` -> `Output/Quilla.FR.bin` (the file name is spelled out because Keil `@L` truncates `Quilla.FR` at the dot) |

`QAPP_BUILD` relocates VTOR to `0x7000` in `../Src/system_py32f040.c`.

### FreeRTOS configuration

`../Middlewares/Third_Party/FreeRTOS/Source/include/FreeRTOSConfig.h` is the
only config, shared with the GCC build. `FreeRTOS.h` includes it with quotes,
so it takes precedence over `../Inc`. Edit clock, tick and heap there.

### Self-contained secver

`../Inc/qfr_secver.h` is owned by the appliance. It includes no Quilla
header, so armcc v5 needs no compatibility macro. `QFR_SECVER_PLACE()`
emits the 8-byte `QAV1` region into `.ARM.__at_0x08007400`; armlink places it
at that absolute address, so no hand-edited scatter region is needed and Keil
regenerating the `.sct` cannot lose it. The section is inside the signed
image, which SEALED / SEC require. GCC uses the `.quilla_secver` section name
from the same header, pinned by `../gcc/py32f040xb.ld`.

All include paths stay inside `appliance/`. Copying this directory to a
location with no Quilla checkout still builds.

### Clock handover: deliberately different frequencies

QBOOT keeps upstream's **48 MHz** (HSI 24 MHz + PLL x2); this appliance runs
at **72 MHz** (HSI 24 MHz + PLL x3, `FLASH_LATENCY_2`). QBOOT does not reset
RCC before the jump, so `app_clock_init()` calls `HAL_RCC_DeInit()` right
after `HAL_Init()` and then builds the 72 MHz tree from scratch, setting
`SystemCoreClock = 72000000U`. `configCPU_CLOCK_HZ` is 72 MHz. Neither
image's clock setting was changed to accommodate the other.

The reset also fixes a HAL quirk: `HAL_RCC_GetHCLKFreq()` returns the
*variable* `SystemCoreClock`, and `HAL_UART_Init()` derives BRR from it.
Inheriting a 48 MHz clock with a stale reset-value variable produces ~6x baud
and a garbled `[QAPP]` stamp. Each image computes 115200 from its own PCLK
(72 MHz gives an exact BRR of 625).

## Build

Open `Quilla.FR.uvprojx` in uVision and press F7, or use the command line:

```
UV4.exe -b Quilla.FR.uvprojx -j0 -o build.log
```

Output: `Output/Quilla.FR.bin`. Keil creates `.uvoptx`, `Objects/`, `Output/`,
`DebugConfig/` and `RTE/` on first use; all are ignored by git.

## Verified build

`UV4 -b` completed with **0 errors, 0 warnings**:
`Code=10544 RO-data=444 RW-data=120 ZI-data=12704`, bin 11108 B.
The binary reports MSP `0x20003218` (< `0x20004000`, so QBOOT accepts the
handover), reset vector `0x08007151`, and `QAV1` version 1 at offset `0x400`.
Packing it with the real `QBOOT_CHECK.bin` and running
`tools/qboot_image.py verify` both pass.

**Hardware check (2026-11-06):** on a PY32F040 board with QBOOT_SEC, the
72 MHz appliance printed `[QAPP] Quilla.FR V1.0.0001`, answered `swqboot`
by returning to the QBOOT banner, and drove the board LED (PB2) with a 1 s
ON / 1 s OFF beat. A full signed QIAP upgrade cycle (GUI updater, this
11108 B image) also passed twice with `ACK_SIGN 0x84`, including the
APP -> QBOOT switch before the second upgrade.

## Do not mix toolchains

The GCC build links `portable/GCC/ARM_CM0/port.c`; the Keil build links
`portable/RVDS/ARM_CM0/port.c`. Keep separate object directories. Both projects
compile the same `../Src` and `../Inc` sources; all include paths stay inside
`appliance/`.
